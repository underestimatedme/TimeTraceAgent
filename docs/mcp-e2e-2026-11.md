### 观察（没有改产品代码，没有新增优化）

1. **派活的提示词里没有任务 id。** ①和②里模型先用分支号猜 id（"未找到"），再摸索：①靠 `start_session`（它会返回自动绑定的任务）找到，②要去 `env | grep`——批准的话会把令牌打印进模型上下文。③的提示词让它先 `start_session`，就没有这个问题。这是一个发布前的可选改进（在 Agent 给模型的说明里写"先调用 start_session，它会告诉你任务"，或在本地先拒绝会输出环境的命令）；本次没做。
2. **派活的 Claude 默认带上用户自己的全部 MCP 服务器**（`--mcp-config` 是追加，不是 `--strict-mcp-config`，见 `adapters/claude.py` 的注释，是有意的设计）。这台机器上用户范围有 `ms365`，每一轮上下文增加约 83 万 token（单次模型运行的数据见 Valley 的联调记录）；派活的成本因此很高，且那些服务器的工具对这次运行也是可见的（需要权限时同样走手机审批）。我没有为此改配置。
3. 取消之后的会话仍是 `active` 直到变成"可能已停止"；取消之后 Agent 对 Valley 的最后一次回报可能被 409 拒绝并留在本机队列（②出现，③没有）。都是现有行为，列在此处不下结论。
