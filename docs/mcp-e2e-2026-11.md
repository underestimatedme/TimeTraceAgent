## 联调发现并修掉的真问题

- **Codex 自己把令牌写进磁盘**（`8260947f…` 那次发现）：`CODEX_HOME/shell_snapshots/<线程>.sh`（权限 644）里有一行 `export TIMETRACE_MCP_TOKEN=ttm_…`，运行结束后还在。令牌那时已经被 Valley 作废，但文件是个持久副本。修复 `cb3b3a2`：带访问的运行加 `-c features.shell_snapshot=false`；有先失败的单元测试；第三次派活之后目录里没有快照、扫描 0 处。
- 之前批次里真实客户端才暴露的两项（`8bc5051`）：Claude 的 `--mcp-config` 吃掉 prompt；Codex `exec` 的审批策略是 never，MCP 调用被拒（现在只对 timetrace 这个服务设 `default_tools_approval_mode="approve"`）。本次真实派活里这个设置生效：AI 的每一次 MCP 调用都执行了。
