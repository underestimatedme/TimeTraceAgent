# TimeTraceAgent 0.6.1

Adds `codex.network_domains`, so a Codex task run can reach named domains, for example `*.apple.com` for an App Store release. Network off stays the default and nothing changes until the list is set. Execution protocol remains 2, and the server does not need an upgrade.

- Other domains are refused by Codex's proxy, including Git hosts over HTTPS and SSH. Do not list a Git host.
- `*`, `*.com`, an address, a URL or any unreadable entry leaves the whole list unused and the network off. Folder and chat runs never get the network.
- The option uses `network_proxy`, which Codex 0.165.0 marks experimental. Check it again after a Codex upgrade.
- A Codex run has no per-command approval. With a domain listed, every Codex task on that computer can call it with the credentials the computer holds, and with `*.apple.com` and an App Store Connect key that includes submitting a release. Leave the list empty unless you are releasing.
- SAFETY_RULES still keep a run to its working directory: keep release tooling in the project's repository.

Validation before release: the Python 3.12 test suite, `codex sandbox` checks, and real `codex exec` runs on Codex 0.165.0 (start and resume) covering allowed and refused domains, a commit in a linked worktree, and a read-only App Store Connect query. No write to App Store Connect has been made through this option. Details are in [the security review](../SECURITY_REVIEW.md).
