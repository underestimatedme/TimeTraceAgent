# TimeTraceAgent 0.6.15

电脑登录过期时，Agent 会直接说明。以前 `timetrace agent doctor` 仍显示「配对: 已完成」，后台 Runner 每分钟写一行 `inventory push failed: CloudError`。

- 服务器拒绝续期时，`daemon.log` 只写一次：「电脑登录已过期或已在手机上解绑」，并提示运行 `timetrace cloud login` 重新绑定。服务器对登录过期和在手机上解绑的回答相同，所以两种情况都会提到。
- 之后 Runner 不再每分钟写 `inventory push failed`，也不再每分钟向服务器重发被拒的凭据：它每分钟检查钥匙串里是否有新的绑定，被拒的凭据先隔 5 分钟再确认，之后间隔逐次加倍，最长 1 小时。
- 本机凭据不会被删除，`timetrace cloud login` 沿用原来的电脑记录。重新绑定后，运行中的 Runner 在下一轮（约一分钟内）用上新登录，日志写一行「电脑登录已恢复」，不需要重启。
- `timetrace agent doctor` 不再只凭钥匙串里有凭据就显示「已完成」，会向服务器续期一次来确认（10 秒超时）：
  - 服务器拒绝：`配对: 登录已过期或已在手机上解绑 → 运行 timetrace cloud login 重新绑定`，doctor 退出码为 1；
  - 连不上服务器或服务器出错：说明这次没能确认，不判为过期；
  - 登录正常：`配对: 已完成，服务器已确认登录有效`。
- 只有服务器用自己的 401 答复拒绝续期才算过期。断网、超时、5xx，或不是服务器给出的 401（例如代理），都照常重试。
- 访问令牌被拒、但仍能续期时，行为和日志与以前相同。

背景：Valley 修复前（Valley #312），电脑登录在配对 30 天后固定过期；修复后，持续在线的电脑会自动延续登录。这一版只改变电脑端的说明方式，不能恢复已经过期的登录：在修复前配对、已超过 30 天的电脑，仍需用 `timetrace cloud login` 重新绑定一次（扫码，并在电脑上输入手机显示的 4 位数字）。

`timetrace cloud status` 仍只读取本机钥匙串，不向服务器确认。

发布前没有用线上 Valley 实测过期答复。判断依据是 Valley 现有续期接口的答复（HTTP 401，代码 40100），测试使用模拟服务端。不需要更新服务端。

通过 Homebrew 安装的用户运行 `brew update && brew upgrade timetraceagent`。等正在执行的任务结束后，运行 `timetrace agent install` 重载后台 Runner，再用 `timetrace agent doctor` 核对状态。
