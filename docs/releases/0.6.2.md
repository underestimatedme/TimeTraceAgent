# TimeTraceAgent 0.6.2

A step whose run started and then stopped without a checkpoint can be retried again.

- The Agent still refuses to restart such a Plan on its own: the earlier run may have left changes or side effects. It now reports the refusal as `failed` instead of `waiting_input`, so Valley offers the person a retry. A `waiting_input` refusal had no way out: nobody could answer it.
- When the person confirms in Valley that the earlier run has stopped and retries, the claim carries `recovery_confirmed`. The Agent then starts the Plan afresh, once, for that new job. A job that was already refused is never restarted by a later confirmation, and a Plan with a checkpoint still resumes from it.
- Needs a Valley version that sends `recovery_confirmed`. With an older Valley the retry is accepted but sends no confirmation, so the Agent refuses the new run again, as before.

Execution protocol remains 2. Validation before release: the Python 3.12 test suite.
