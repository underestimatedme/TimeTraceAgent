# TimeTraceAgent 0.6.5

The local queue (`timetrace run`) can run beside an online agent (`timetrace agent run`), and the login diagnostics tell "signed out" from "cannot verify".

## Queue beside the agent

- Up to 0.6.4 both commands took `agent.lock` exclusively, so the queue could not start while the agent was online. Now the agent holds `agent.lock` shared (plus `agent-role.lock`, so there is still one agent) and the queue holds it shared beside the agent, exclusively when alone. The queue takes only tool slot 0 and overall slot 0, so the agent's and the queue's jobs together stay inside the agent's configured limits, which remote configuration may lower at any time.
- An older `timetrace run` or `timetrace agent run` takes the lock exclusively and without waiting, so it cannot start while a 0.6.5 agent or queue is online, including the moment the agent leaves. It therefore cannot reset a running task to `runnable` or run it a second time. A 0.6.4 agent that is already online holds the lock exclusively, so the 0.6.5 queue refuses to run beside it ("upgrade the agent first"): fail closed.
- Under its slots the queue re-reads the task and runs it only if it is still `runnable`. A task left `running` by a queue that really died is reset by the next queue and resumes with its session after any crash fence has been cleared by hand.
- A queue running alone still holds `agent.lock` exclusively, so an agent cannot start beside it: start the agent first, or stop the queue.

Upgrade order, rollback and the handling of `local_pause.json` (which survives restarts) are in [queue-beside-agent-upgrade.md](queue-beside-agent-upgrade.md). Unreleased candidates that printed 0.6.4 (73b5971, 73dcbc1) must not be mixed with a released build.

## Login diagnostics

- `timetrace agent doctor` separates "signed out or login expired", "billing mode does not match" and "cannot verify", and keeps the raw reason code. A signed-out Claude (`claude auth status` exits 1 with `loggedIn: false`) is reported as not logged in; a failing Codex status command is `auth_status_unavailable`, not a re-login prompt.
- The hints print the login command for the CLI that was actually found. Nothing logs in or changes tool configuration automatically.

Execution protocol remains 2, and the server does not need an upgrade. Validation before release: the Python 3.12 test suite (1028 tests) and the forced-timing and upgrade/rollback matrix in `docs/queue-beside-agent-upgrade.md`.
