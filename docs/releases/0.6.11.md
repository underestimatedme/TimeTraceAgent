# TimeTraceAgent 0.6.11

TimeTrace 现在能看到三样新东西：AI 对自己这一步做得怎样的说明、你在电脑上直接用 AI 做了什么，以及 TimeTrace 派发的每次运行用掉多少 token。

- **AI 完成说明。** 执行步骤可以在 `.timetrace/out/result.json` 里写 `report`，给出结论（`success`、`needs_review` 或 `blocked`）、摘要、没做完的事和建议复核的地方。电脑端先脱敏再截断：摘要最多 1000 字，「没做完的事」和「建议复核的地方」各最多 10 项，每项最多 300 字。处理后随结果交给 Valley，控制台在步骤和验收处显示。结论无效或字段类型不对时，只丢弃 `report` 并在完成说明里注明；列表里的空项和非文字项会单独略过。它只供参考，不改变验收结论。
- **本机 AI 会话记入（默认关闭）。** 在 TimeTrace 网页「设备」页打开后，你在终端或桌面端直接用 Claude Code / Codex 做的事会记入「按日回顾」。只记工作目录在已登记工作区内的会话，TimeTrace 自己派发的运行不重复记入。首次打开时，本机已有的历史会话也会记入。每段会话只上传元数据：工具、会话 id 摘要、工作区、模型、分支、起止时间、提问次数、token 合计和改动文件数。对话文字（包括标题）、命令输出、文件路径和内容都不上传。关掉开关后，Valley 立即拒收新记录，电脑端在下一次心跳（默认约 30 秒）后停止读取。已上传的记录可在同一页删除。
- **AI 用量。** TimeTrace 派发的运行结束时，会上报本次用掉的输入、输出、缓存读取、缓存写入 token 和模型名。结束包括完成、失败、被中断、取消，以及暂停等待额度、输入或本机登录。数据不可靠时（例如 Codex 续跑找不到可靠的起点）不上报，不做猜测。Codex 续跑只计本次新增的部分。`codex exec` 不给出模型名时，从该会话的本机记录读取。
  控制台的「AI 用量」页按日、项目、来源和模型汇总，并按 models.dev 2026-11-16 的公开标价估算费用。认不出的模型不估价。一次 Claude 运行用了多个模型时，按用得最多的那个计价。估算不等于账单，订阅套餐不按 token 收费。
- **ACP 客户端，不派发 Gemini CLI 和 Cursor。** 新增只依赖 Python 标准库的 Agent Client Protocol 客户端。Gemini CLI 和 Cursor 可以登记，并在 `timetrace agent doctor` 里查看。但它们的零付费和凭据隔离无法核验，核验结论固定为未通过，TimeTrace 不会给它们派发任务，新任务和续跑都一样。

这些功能需要配套更新的 TimeTrace 用户控制台和 Valley。用量统计已在 macOS 上用 Claude Code 2.1.325 和 Codex 0.165.0 的真实运行核对，Codex 包括续跑，核对数字见 #39。已有配对和工作区配置继续沿用。

Homebrew 用户可运行 `brew update && brew upgrade timetraceagent`。等当前任务结束后，运行 `timetrace agent install`，再用 `timetrace agent doctor` 检查运行版本。
