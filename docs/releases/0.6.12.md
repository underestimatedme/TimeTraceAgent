# TimeTraceAgent 0.6.12

验收一个步骤时，TimeTrace 现在会把电脑自己记录的运行事实放在 AI 完成说明旁边：执行了多少命令，哪些被识别为测试命令、最后一条结果如何，以及这次交付改了多少。AI 的说明是它自己的说法，运行事实来自电脑看到的过程，两者可以对照。

- **运行事实。** TimeTrace 派发的运行结束并等待验收时，电脑端会随完成事件上报 `run_facts`：
  - **命令：** 执行次数和失败次数。数据来自 Claude Code 和 Codex 自己的事件流（Claude Code 的 stream-json、`codex exec --json`、Codex App Server），不读 AI 写的任何文件。事件流里有读不了的行时，不报命令事实，也不会用 0 代替。
  - **测试：** 按命令行识别 27 种常见测试运行器，例如 pytest、go test、npm test、cargo test、xcodebuild test。只列出、试运行或跳过测试的命令不算。
    - 只有当测试运行器是整条命令的最后一段，并且输出里有该运行器自己的汇总行时，才记为“成功结束”。
    - 退出码可能来自命令的其他部分时，结果记为“无法确认”。
    - 识别靠推测，自定义检查可能认不出来。
  - **改动：** 这次交付的文件数、其中非文档文件数、增删行数，以及没有提交、因而不在交付里的新文件数。
  - **续跑：** 从检查点续跑的运行只记到续跑之后的命令，上报时会标明。
- **只上传计数。** 上传的只有计数和固定的测试运行器名称，命令文字、输出和文件路径都不上传。汇总行只在本机匹配。
- **控制台对照。** 控制台在 AI 完成说明下方显示「电脑记录」。只有一种情况会标为「不一致」：AI 说已做完，但最后一条测试命令以失败结束。其他情况都只是提示，例如之前有测试命令失败过、改了代码但没看到测试命令、有新文件没提交。这些都不改变验收结论。

这些功能需要配套更新的 TimeTrace 用户控制台和 Valley；旧版 Valley 会忽略这个字段。事件格式已用 Claude Code 2.1.325 和 Codex 0.165.0 的真实运行核对。已有的配对和工作区配置继续沿用。

Homebrew 用户可运行 `brew update && brew upgrade timetraceagent`。等当前任务结束后，运行 `timetrace agent install`，再用 `timetrace agent doctor` 检查运行版本。
