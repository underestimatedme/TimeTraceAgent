# TimeTraceAgent 0.6.4

A command that copies or moves the run's own result files is no longer refused as "访问凭据".

- The model writes structured results to `.timetrace/out/` inside its worktree. Shell commands that named that directory by its relative path, such as `cp .timetrace/out/notes.md docs/`, were refused as credential access, because the rule matched any `.timetrace/` in the command text. The same files could still be read and edited with the file tools, so only shell copies and moves failed (seen on a real App Store task on 2026-11-11).
- A relative `.timetrace/out` or `.timetrace/out.prev-*` reference is now treated as part of the worktree. Commands that needed approval before still need approval; nothing new is allowed automatically beyond read-only commands inside the worktree.
- Still refused: `~/.timetrace`, `$HOME/.timetrace` and `../` paths, any other name under `.timetrace`, commands that change directory (`cd`, `pushd`, `popd`), and an output directory that is a symlink leading outside the worktree.

Execution protocol remains 2, and the server does not need an upgrade. Validation before release: the Python 3.12 test suite.
